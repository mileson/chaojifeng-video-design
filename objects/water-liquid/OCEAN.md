# 开放海面构建配方

用于海面近景、低掠镜头与开放海域。目标是在同一场景中形成大中小波形、随视角变化的太阳与天空反射、蓝绿水体层次和稳定的远景覆盖。海岸破碎、焦散、水下穿越和物体交互需要各自模块，不由此配方自动提供。

## 从一个完整预设开始

先读取 [设计方法](METHOD.md)、[工程指南](ENGINEERING.md) 和 [画质构建与排错](QUALITY.md)，再运行本配方。已有验证实现优先复用，不从通用海洋修改器加默认材质重新猜起。预设包含尺度、运动、相机、照明、水体与渲染设置；复制到本次作品目录调整，保持 Skill 内的基准配置稳定。

从零构建必须只依赖本配方的代码、配置和已安装的 Blender。不得依赖历史作品的绝对路径、修补脚本执行顺序或临时工程。实际命令与参数见下方运行入口。

## 固定对照条件

先保持同一机位、焦距、时刻、随机种子、曝光、采样和输出尺寸，逐组改变参数。几何变更时重新检查相机净空与远景覆盖，不能拿不同构图的图片证明某个参数更好。

| 参数组 | 怎样调整 | 必须同时观察 |
| --- | --- | --- |
| 频谱尺度与风浪 | 先确定世界长度，再调风速、方向和波能量 | 实测浪高、峰谷间距、周期感、平铺重复和采样密度 |
| 位移与水平挤压 | 用预设起点，小幅增减后测波面 | 相机是否进入液面、峰顶是否翻折、自交或形成黑三角 |
| 中小尺度 | 分别控制几何细节与微表面 | 轮廓、法线、高光破碎、远处闪烁，避免仅添加静态噪声 |
| 照明与环境 | 先调整太阳与相机夹角，再调环境明暗 | 亮带位置、云层倒影、暗部层次与高光纹理 |
| 水体光学 | 根据光程标定吸收，配合表面反射 | 近远水色、透明范围、是否偏黑或出现不自然绿斑 |
| 渲染质量与成本 | 同帧对照采样、降噪与反弹上限 | 细节保留、噪点、色阶、设备与帧耗时；不只看编码尺寸 |

引擎中的位移倍率不等于米，频谱域长度也不等于某一条浪的波长。参数合法范围只表示实现接受，实测安全范围还取决于机位和波相。不能把一个范围写成适合所有场景的物理定律。

## 三个验证阶段

1. 构建与检查。读取有效配置，检查模块、输出路径、网格成本、全程相机覆盖及液面净空；确认不依赖外部历史工程。
2. 同帧对照。先用低成本代表帧定位形态和照明，再用原生交付尺寸检查高光、微表面与远景；每次只改变能解释结果的一组参数。
3. 连续基准。固定时间范围渲染短片，检查波相推进、微波是否连续、曝光和高光是否跳变；用同一帧重复与乱序求值检查可复现性。通过后接入作品主时间线。

检查相机时，少数采样时刻只覆盖采样范围。实际视频仍要检查连续运动及相机极值；数值安全不能代替画面通过。基准短片不自动具有声音，声音按作品主计划另外编排和听审。

## 接入作品时间线

基准使用局部帧1对应0秒；进入作品时由已有主计划的镜头起点和帧率派生局部帧，不另维护事件时钟。配置的时长与相机终点取自该镜头，分段渲染保持同一份配置，只改变请求的帧范围，不能每段把时间重置为0。`ocean.time_speed`只调整频谱层的艺术速度；整片慢动作须统一重映射主时间，不能只减慢该参数。

## 扩展与交付

新镜头从预设派生，记录配置差异及原因，不改写基准结果。不同设备渲染先比较结构、时间和图像容差，不承诺跨设备逐像素相同。代码、预设、有效参数、构建状态和实际画面分别保存；审片结果写项目，不能靠脚本默认填写视觉通过。

公开成片保持正常画面，参数、检查结果和执行记录留在工程。交付可播放视频与可重建工程；资源不足时先限制验证规模并定位成本，不把缺失模块或未验证画面当作完成。

## 运行入口

先核实 Blender 可执行文件。BLENDER 与 SKILL_ROOT 使用当前机器实际路径；不安装软件、不启动后台服务。输出指向本次作品目录，避免覆盖旧作品。

```sh
"$BLENDER" --background --python-exit-code 1 \
  --python "$SKILL_ROOT/objects/water-liquid/runtime/build_ocean.py" -- \
  --config "$SKILL_ROOT/objects/water-liquid/runtime/presets/open-ocean.json" \
  --output /path/to/project/ocean --mode build
```

构建通过后渲染代表帧：

```sh
"$BLENDER" --background --python-exit-code 1 \
  --python "$SKILL_ROOT/objects/water-liquid/runtime/build_ocean.py" -- \
  --config /path/to/project/open-ocean.json \
  --output /path/to/project/ocean-preview --mode frame --frames 1,12,24 \
  --quality preview --device CPU
```

原生画质验证使用 `--quality native`。`--mode frame --frames 1,12,24` 只渲染三个离散帧；`--mode clip` 不指定帧时默认渲染第一秒，显式指定时必须列出连续帧，不能把三个离散帧当作短片。连续渲染有配置预算上限，正式长片由作品按主时间线分段执行。Metal 仅在当前机器探测可用后显式选择 `--device METAL`，不修改全局 Blender 偏好。PNG 序列编码沿项目既有 FFmpeg 工作流，编码前核对帧范围、帧率、缺帧和尺寸。

`effective-config.json` 保存实际配置，`measurements.json` 保存实测状态，`manifest.json` 保存运行信息，`scene.blend` 保留可编辑的单帧场景快照；动画由构建脚本按绝对帧求值，直接拖动该快照的时间线不会重新计算液面，`frames/` 保存实际渲染帧。运行成功不自动标记视觉或参考质感通过。以实际生成文件及脚本帮助为准。

字段单位、校验范围与参数联动见 [参数说明](runtime/PARAMETERS.md)。配置范围表示本实现的可接受输入，不表示全部组合已获得视觉验收。
