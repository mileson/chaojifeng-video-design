# 从内容到画面

先确定观众、看完应知道/相信/会做什么、哪些事实支持、什么证据必须上镜。将“科技感、电影感”翻译为产品适合的材质、层级、运动与声音选择，不能只堆蓝光粒子，也不固定每片采用同一美学。

| 内容关系 | 可以怎样呈现 | 易误导的做法 |
| --- | --- | --- |
| 步骤/任务 | 同一对象按触发与结果推进 | 同时播放多窗口却要求顺序理解 |
| 因果/分支 | 命名节点、方向、条件和反例 | 把相关画成因果或省掉条件 |
| 对比/前后 | 同尺度与主体，突出变化 | 换尺度、遮基准、面积夸大 |
| 数量/比例 | 真实标注、一致单位、适量插值 | 无数据却画貌似真实统计图 |
| 功能状态 | 初态→触发→变化→终态 | 产品并无能力却用动效造结果 |
| 故事情绪 | 主体、目标、阻碍、转折连续 | 漂亮镜头拼接后事件失联 |

截图承担界面证据，图示承担关系，照片承担对象或情境。生成图不冒充真实功能、人物或事件照片。联网素材保留原链接、作者/许可可得信息和用途，不能编事实填空。

界面操作、结果或关键数据需要强化时，读 [视觉强调](visual-emphasis.md)。先确认完整目标与必须保护的内容，再选框、短标签、引线、局部放大或错时强调；不把每个镜头都变成教学标注图。保留真实前后状态，标注跟随画面映射，单点免多余编号，样式按本片品牌决定。

分开决定叙事、风格、布局、镜头和动效。叙事安排理解顺序；风格安排颜色/字体/材质/运动气质；布局表达空间关系；镜头安排焦点与停留；动效执行具体变化。品牌覆盖默认token，横竖屏和长中文可能要换布局，不只缩字。

品牌形象片可由视觉母题、情境和声音建立感受，但愿景须与现有能力分开。音乐／视觉表演可由动机、段落与变奏组成，不必有角色或论证。两者都需要可辨的段落变化与收束。先读导演方法，按需使用表达与配方目录；不要强迫所有片型走同一结构。

每个画面写 viewer takeaway、焦点对象、变换、文案/声音、停留/退出。运动应能说明帮助注意或解释什么；复杂知识允许少动、拆镜或延长。recipe是起点，compose处理局部，free处理独特任务；自由不免检查。不要因为目录存在就强迫套用，也不因模型版本强就免验。

用户未要求先评方向时，低风险选择自行决定并继续。简单任务不生产大量独立文档。examples三份计划是原创结构样例，不代表已渲染、已观看或理解提升，替换事实与素材后重核时间和能力。

## 场景、视觉角度、代码与动效一起推导

设计 B-roll 或其他代码构建的画面时，先说清这个场景中“谁与谁是什么关系、发生什么变化、观众应得到什么”。B-roll 有对应口播、字幕或主画面时，同时核对它承担的是补充解释、提供证据、建立情境还是承接情绪，以及可用时长。场景可以是现实事件、产品操作、抽象机制或情绪推进。视觉角度指把其中哪种关系变成可见的空间、形态或状态，不只指相机角度。沿 **场景关系 → 视觉角度 ↔ 代码构建 → 动效表达** 推导，并用观众所得回查每个选择。

| 决策 | 要建立的关系 | 落到画面与实现 |
| --- | --- | --- |
| 场景为什么需要这幅画面 | 内容中的关系或变化 → 观众要理解或感受的事 | 如“条件解除后任务才能继续”，先保留条件、对象身份与前后状态 |
| 为什么从这个角度呈现 | 内容关系 → 可感知的空间、形状、数量、遮挡、材质或视点 | 如把依赖呈现为通路的阻断与接通；说明它比单纯列出步骤多表达了什么 |
| 什么代码方式适合构建 | 可见关系 → 对象、状态、几何规则、约束与可调参数 | 如由任务状态共同决定通路、对象位置与结果显现，避免三套无关动画各自表演 |
| 动起来怎样表达得更好 | 语义变化 → 动作先后、速度、响应、停留与接力 | 如先建立阻断状态，解除后才推进下游，再留出结果阅读；运动兑现条件关系 |

这不是单向填表。路径、遮罩、程序化排布、层级变换、参数化形变等代码机制，也能启发新的视觉角度：同一组对象可以按关系聚合，也可以沿路径展开。对关键镜头提出有实质区别的候选，以表达贴切程度、画面吸引力、阅读负担和实际能力取舍；不能只换颜色或换对象。能力不确定时按 [镜头生产统筹](shot-production.md) 做最小必要试验，再修正构想或路线，不先把引擎名当成方案。

### 把选择的理由写出来

下表是推导示例，不是固定配方；其中的空间比喻不替代产品功能证据或真实数据。

| 场景关系与观众所得 | 视觉角度及理由 | 代码构建方式 | 动效为什么这样安排 |
| --- | --- | --- | --- |
| 从许多材料中筛出符合条件的部分，让筛选依据可见 | 保持对象身份，让同一规则作用于所有对象；保留落选对象作参照，结果不是凭空出现 | 为对象保留标识和条件状态，由规则生成分组位置、遮罩或强调范围 | 先让条件可读，再呈现分流，最后保留选中与未选中的对照；快闪会掩盖依据 |
| 一项任务在多个环节间交接，让责任与连续性可见 | 跟随同一任务穿过不同空间，每次交接改变归属；比多个窗口同时闪烁更容易追踪同一件事 | 以任务进度驱动路径位置、归属状态与接收方响应；交接前后维持共同锚点 | 任务先到达，接收方再响应，上一方退出；若业务实际并行则保留并行，不为整齐改成串行 |
| 条件解除后下游才开始，让依赖关系可见 | 可以用被阻断的通路，也可以用无法展开的层级结构；按受众熟悉程度和本片空间选择 | 把依赖写成状态约束，联动通路开放、层级展开或下游进度 | 先建立等待，再显露触发与连锁结果；同时启动所有元素会抹掉因果 |

代码擅长维持关系和生成变化，但复杂度本身不构成吸引力。构图可用清楚的大轮廓与局部细节、重复中的差异、稳定区域与局部变化形成观看重点；再让观众看到一次与场景意义一致、值得期待的变化。选择哪些手法取决于内容和情绪，不要求每镜都有反差、悬念或高运动量。静态已经表达清楚时，动效只承担必要的揭示、交接或节奏。

### 风格参与表达，具体形象随场景选择

形状语言、线条、色彩、材质、字形与运动气质共同决定画面的感受。例如柔软形变、精确机械运动、分层纸片移动各自暗示不同的物性和情绪，应与当前内容匹配。纹理要决定附着在哪个对象或空间，线条和字形要在目标尺寸可读；不把全屏噪点或统一弹跳当成风格。按需从既有 [风格包](style-pack-contract.md) 借用规则，并交代哪些保留、哪些随内容变化。

迁移时保留“为什么用这种视觉关系、什么构建机制使它成立、动作怎样解释变化”，重新选择主体、构图与材质。换一个形象仍照搬同一场景，不算完成方法迁移；换内容后表达关系不再贴切，就应重选角度。同一套方法应能导出有角色、无角色、几何、文字或真实素材参与的不同结果。

方向可记入现有 [方向模板](../templates/direction.md) 或镜头说明：场景关系 → 视觉角度与取舍 → 代码中的控制关系 → 动作与停留 → 验收依据。无需新增必填字段或独立文档。具体落地读 [表达实现](expression-method.md)，研究新参考读 [参考片研究](reference-film-study.md)。检查观众能否辨认主体和前后变化、动效是否保留原有关系、风格是否帮助表达；渲染成功和个人审美判断都不能单独证明观众理解或传播效果。
