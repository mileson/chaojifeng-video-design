# 真实界面成片的工程要点

适用：[源码说明片](product-source-explainer.md)这类用产品真实界面逐帧渲染、带旁白、乐床和字幕的成片。浏览器扩展与 Web 应用直接照做，其他形态借用时间驱动和取证规则。方法来自一次完整制作：浏览器扩展“一键发”，9:16（1080×1920）、25 fps、约 98 秒，2026-11-05 完成并实测。第一版的通用声被用户评为“音色单调、语速慢”，第二版改用本人声音、提速到约 63 秒，旁白重做后的时间映射见下文；第三版按用户要求在最前面加了痛点钩子与揭晓，约 75 秒，开场前置后的时间映射也见下文。

目录：渲染路线 · 取证夹具 · 镜头与事件 · 渲染与续跑 · 声音链路 · 旁白重做后的时间映射 · 开场前置后的时间映射 · 编码与检查 · 常见问题

## 渲染路线

- 画面由两层组成：外层页面负责排版（标题、副标题、画板、字幕、品牌卡、片尾），里面用同源 iframe 加载真实界面。镜头不裁整屏，而是对 iframe（如 1440×900）做 CSS 缩放与平移。
- 所有视觉量都是整片时间 t 的函数，界面状态由按时间排序的幂等事件推进。页面只暴露两个入口：`prepare()` 做准备并返回时长，`advanceTo(t)` 推进到 t；渲染脚本逐帧调用后截图。
- 时间只有一个来源：词级排程 `schedule.json`（beats 与 clauses）。字幕、镜头、光圈、点击、音效和闪避都用 `bs/be/cs/ce`（beat 起止、分句起止）取锚点再加偏移，不另写绝对秒数。改配音后重跑排程，整片跟着动。
- 计划与交付登记用脚本从同一份排程生成，镜头和光圈的时间公式与场景引擎一致，计划才能如实记录实现。

## 取证夹具

1. 用源码自带的预览入口（夹具）在普通页面里渲染真实页面；本机静态服务只绑 `127.0.0.1`，已有服务就复用。
2. 浏览器用本机已缓存的无头 Chromium，不执行 `playwright install`。路由只放行本机，其余请求一律拒绝，图片从本地缓存供给，这样不会碰任何真实平台。
3. 平台图标按源码里的地址预先缓存。无头 Chromium 解不了 ICO，先转 PNG；以 `favicon.ico` 结尾的地址会绕过路由，给地址加无害查询串（如 `?mv=1`），路由里再剥掉。
4. 账号、昵称、文章链接用受控的人设数据，覆盖产品自己的账号检测函数。iframe 同源，可用 `contentWindow` 取文档；脚本里的词法全局变量用 `contentWindow.eval` 读写。
5. 状态变化走产品自己的渲染函数（状态设置、弹层开关、列表渲染），不手改 DOM，画面才是真实组件的结果。
6. 引导图、商店图、截图里的第三方公开昵称、邮箱和头像逐张看过再用；商店快照存档时去掉开发者邮箱。
7. 取证帧挑代表画面归档到 `assets/evidence/`，账本里的 `evidence` 逐条登记怎么取、哪个版本、哪天。

## 镜头与事件

- 镜头规格三种：`sel`（选择器，取外接矩形加边距）、`rect`（固定区域）、`region {x, y, w}`（给宽度和左上角，高度按画板比例推出，`y` 可为负以露出上方内容）。选择器外接框会带进邻居时改用 `region`。
- 移动用宽度取对数插值、中心线性插值，缓入缓出。目标区域逐帧实时量取，布局变化后仍然对准；量不到就沿用上一次有效值。
- 光圈、点击涟漪、光标、打字、滚动都是 t 的函数。`click` 同时登记涟漪与音效，并在同一时刻触发真实点击。
- 事件幂等：同一时刻重复触发结果不变。推进按步进（每步不超过 0.25 秒）执行，让时间驱动的事件依次触发；iframe 里的 CSS 动画暂停，并把 `currentTime` 设成 t。
- 章节切换让画板短暂淡出再淡入，界面重置放在淡出最低点，观众看不到状态跳变。
- 镜头对不准先量元素矩形再改数值，不凭肉眼估。

## 渲染与续跑

- 一次只开一个浏览器，逐帧存 JPEG（质量约 93），每 50 帧打印进度，支持 `--start-frame`、`--end-frame` 续跑和局部重渲。
- 长任务放后台运行。在 Cursor 的 Shell 工具里用 `block_until_ms: 0`；在调用里写 `nohup … &` 会在调用结束时被杀，渲染会停在半路。
- 中断后用起始帧续跑，再核对总帧数、有没有异常小的文件、接缝帧是否连续。局部修改只重渲受影响的帧范围，改了时间就整段重渲。

## 声音链路

- 旁白：通用声走本地 Qwen3-TTS 整稿一次合成，逐分句拉平电平，见 [Qwen 配音接入](qwen3-tts-narration.md) 第 6 节；超级峰自己的作品用本人声音，分段多取样择优后拼接，见 [讲解配音的声音方向](narration-voice-direction.md)。
- 乐床：没有可核实商用范围的素材时，本机用代码合成（和弦循环加分层进入，无采样无曲库），权属清楚。素材库缓存的曲子，如剪映曲库，不能当商用乐床。
- 音效：界面操作（点击、弹出、完成、切换、转场）用脚本合成，事件表单独保存，并把每个事件的时间绑到排程锚点。
- 闪避：人声期间乐床压到约 0.45 倍，起 0.06 秒、落 0.5 秒；乐床电平先单独定到约 −27 LUFS 再混。
- 混音链：人声先 75 Hz 高通，再逐分句拉平、压缩、限幅；总线最后再限幅。

## 旁白重做后的时间映射

换声音或提速后，口播的起止点全部移动，画面不必重新设计。第二版（本人声音，97.9 → 63.0 秒）这样做：

- **两套时间。** 场景仍按“设计时间 τ”写，存为 `schedule-design.json`；实际口播排程另存 `schedule-film.json`（成片时间 t）。两者之间建分段线性映射，每个分句的起点和终点各是一个锚点，句间静音与章节间隙随锚点伸缩。
- **所有视觉量走同一个映射。** `advanceTo(t)` 先把 t 映射回 τ 再推进场景；字幕、镜头、光圈、点击和闪避都从映射后的时间取值，音效事件表用 `getSfx` 把 τ 换成 t。不在映射之外给个别镜头另加补丁；某个画面事件比口播快或慢到不自然，回设计时间线调该章的锚点偏移。
- **口播文字没变，只重做声音相关的部分**：配音、排程、映射、字幕、音效、计划与交付登记；分镜、证据和账本不动。文字变了，按事实重核。
- **顺序固定**：配音 → 排程 → 画面渲染 → 取音效事件表 → 混音 → 编码。渲染会重写音效事件表，混音早于最后一次渲染就会拿旧时间；每次重渲后重新混音，并复核音效起音。
- **核对分句边缘**：用波形能量检查每个分句的起止是否落在有声段边缘（第二版 43 处全部通过），再用 ASR 回读核字；ASR 只管字，不管时间准不准。

## 开场前置后的时间映射

在最前面插入新的开场（钩子加揭晓），后面的章节不动，仍走同一套映射。第三版（61 次配音请求，5 段新口播，75 秒）这样做：

- **设计时间线最前面加一段，原有章节整体后移。** 设计排程里，新开场的节拍写成“新增节拍”，旧节拍保持原来的分句；成片排程由拼接脚本按实际口播生成。两份排程的节拍 id 与每个节拍的分句数必须一一对应，映射函数发现不一致就直接报错，宁可停下，不静默错位。
- **开场的画面也由 `advanceTo(t)` 驱动。** 多幕之间的交叉淡化、盖章、翻转都用分句起止做锚点（实测交叉淡化约 0.28 秒），不写绝对秒数；钩子的各幕共用一层容器，按节拍交叉，不分别开新页面。
- **揭晓处整体切换。** 上一幕整体淡出、品牌卡淡入，再接真实界面；真实界面的重置放在品牌卡最亮的时刻，观众看不到状态跳变。
- **取证夹具不用动。** 钩子画面是独立构图，不显示真实界面，平台图标取自界面页里的站点数据；真实界面部分与第二版一致。
- **音效与乐床随开场重做。** 开场的音效事件进同一份事件表；乐床的开场段按[声音方向](narration-voice-direction.md#开场钩子的声音与配乐)重写。顺序仍是配音 → 排程 → 渲染 → 取音效事件表 → 混音 → 编码。
- **整片重渲不是负担。** 单进程无头 Chromium 渲染 1865 帧约 80 秒，改了时间或开场画面就整段重渲，不做半途拼接。
- **先看单帧再整渲。** 开场新画面先抽 0.1 秒、各句中点、揭晓前后的单帧，在手机尺寸下看版面是否上重下轻、暗色图块是否看得清，再整片渲染；第三版的版面偏移与图块亮度都是看单帧发现的。

## 编码与检查

编码用 FFmpeg，把 sRGB 的 JPEG 帧转成 BT.709 有限范围的 `yuv420p`，音轨 AAC 192k、48 kHz 立体声，`faststart` 并写入标题。下面的参数在 100 帧样段上与交付文件的 x264 选项逐项一致（线程数除外）：

```sh
ffmpeg -nostdin -y -framerate 25 -i build/frames/f%05d.jpg -i build/audio/mix.wav \
  -vf "scale=out_color_matrix=bt709:out_range=tv:flags=bicubic,format=yuv420p" \
  -c:v libx264 -preset medium -crf 17 -x264-params ref=4:subme=8:trellis=2:direct=auto:rc-lookahead=50 \
  -profile:v high -level 4.1 -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv \
  -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart -metadata title="片名" final/片名.mp4
```

编码命令写进项目脚本，不只留在聊天里；交付里的 `source` 要包含它。检查按这个顺序跑，前一步不过不进下一步：

```sh
python3 SKILL_ROOT/scripts/product_ledger.py check ledger.json --source /path/to/product-source --evidence-root . --script script/narration.txt --script qa/public-text.txt
python3 SKILL_ROOT/scripts/validate_plan.py plan.json --strict-assets --strict-timing
python3 SKILL_ROOT/scripts/check_delivery.py plan.json delivery.json --probe --require-video
```

`public-text.txt` 收集全片对外文字（标题、副标题、品牌卡、片尾、字幕与旁白），账本的禁用词同时扫它和口播稿。另做：成片整体解码一遍（`ffmpeg -v error -i 成片 -f null -`）、`ebur128` 测响度与真峰值、ASR 回读比对、界面可见文字扫描、等间隔接触表目视。没有整片连续播放和人耳试听时，视觉、播放、听感如实写 `partial`，观众理解写 `not_run`；`check_delivery` 的状态也因此是 `partial`，这是准确的，不要为了变绿改状态。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 平台图标空白 | 无头 Chromium 解不了 ICO，或 `favicon.ico` 地址绕过路由 | 转 PNG，地址加查询串，路由里剥掉 |
| 界面显示未登录 | 账号检测走扩展接口 | 覆盖账号检测函数，写入受控账号 |
| 光圈偏离目标 | 布局变化后仍用旧矩形 | 逐帧实时量取，量不到沿用上一次有效值 |
| 镜头带进相邻内容 | 选择器外接框含邻居 | 改用 `region` 规格 |
| 渲染停在半路 | 后台命令随调用结束被杀 | 用不阻塞的后台任务，按起始帧续跑 |
| 混音比目标响约 3 dB | 单声道复制成双声道后，立体声读数高约 3 dB 的算法效应 | 单声道文件按 −17.5 LUFS 定，立体声混音约 −14.5 LUFS |
| 旁白越往后越响 | TTS 整稿后半段电平漂移，实测约 +7 dB | 逐分句拉平，单句调整幅度设上限 |
| macOS 上 `sed -i` 报错 | BSD sed 需要备份后缀参数 | 写 `sed -i ''`，或用脚本改文件 |
| 开场画面与额度冲突 | 开场展示的平台数超过普通用户的每日额度 | 不报数字，口播与尾幕小字收窄；能不冲突就让开场不超过额度 |
| 音效对不上口播 | 混音早于最后一次渲染，用了旧的音效事件表 | 渲染后重新取事件表，再混音、编码 |
| 拼接后某句开头有杂音、首字被吃 | 取样开头有短促杂音，或把接口给的首字时间当真实起点 | 忽略短于 60 ms 的有声段，首个起点取与接口首字时间重叠的有声段，详见 [声音方向](narration-voice-direction.md#取样与拼接的坑) |
| 句尾被截 | 接口给的末字结束时间比真实尾音短（实测最多少 0.25 秒） | 以 5 ms 能量包络确定尾音，尾部留余量 |
| 开场改句后映射报“时间表分句不一致” | 设计排程与成片排程的节拍 id 或分句数对不上（例如疑问句拆成了四个分句，设计排程里还是一个） | 先改设计排程里的分句表，再重生成两份排程；不在映射里打补丁 |
| 开场新增画面看起来上重下轻、暗色图块几乎看不见 | 面板高度按真实界面定，钩子内容偏上；暗色背景上的图块底色太接近 | 抽单帧在手机尺寸看，调纵向偏移与图块亮度，再整片渲染 |
