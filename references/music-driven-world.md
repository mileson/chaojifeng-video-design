# 音乐、主题与风格驱动三维世界

三维世界适合本片时，沿 `music-event-performance` 的音乐先行分支执行。用户只给歌曲时，先按 [歌曲视觉导演](song-visual-direction.md) 自主推导主题与风格；用户已指定的优先。主题是理论关系时同时读知识表达；音乐带有说唱不自动改写歌词或生成新曲。保留用户指定原音轨，换曲、静音或重编须有对应指令。

## 三项输入与直接交付

音乐接受可访问链接或本地文件，先复用当前任务的已核实文件；网站操作按宿主 Chrome 路由。主题明确要表达的对象与关系，风格可用已有风格包或项目外观变体；没有指定时由本片导演判断，不将三维设为所有音乐视频默认。缺少时长和规格时默认约60秒、9:16（1080×1920）、30fps，选段尊重完整乐句；已有项目或用户要求优先。

低影响创作选择自主完成，内部关键帧、短段和返修不增加确认节点。必要素材、工具或费用真正阻断时说明缺口。初始化不是成片，不将基础形状当作已完成主题表达。

## 从真实音乐到事件

1. 先核音轨、哈希、长度，回听候选区间，选择有发展、释放和收束的连续乐段。歌词存在时先按 [字幕导演](subtitle-direction.md) 取得带时间戳的实际唱词；无可信稿时探测并尝试可用 ASR／对齐，失败保留具体记录，不能静默省略默认字幕。纯音乐不强加旁白。
2. 复用 `music-cue-sheet.json` 记录原曲与成片的映射。音乐地图绑定源哈希、片段、帧率；起音、拍点、重音、乐句和段落分别记录。速度不稳时用实际锚点序列，不能硬套等距BPM。
3. `music_world.py analyse` 以现有FFmpeg和Python标准库生成粗频带、RMS及候选起音。候选不是已核实节拍或乐句；有分轨/更可靠分析时可以沿原工程替换数据，保留实际方法和范围，不自动安装模型。
4. 选择贯穿对象，写它如何引出下一镜。墨滴→山体→河道，青蓝笔触→器物纹样→烟雨空间，点与向量→投影→曲线都是案例；新题材重新定义，不照搬地名、公式或故事。
5. 记录预备、触发、峰值、落定、回弹和稳定停留。音乐对齐的是有意义的视觉锚点；动作可以提前准备，峰值与落定也可落在不同拍。当前工具的标准顺序是 prepare≤trigger≤peak≤settle≤hold_until；特殊动作需要在项目中扩展并说明。

score.json 为本片有效事件输入；由它与音乐分析生成 public/job.json，渲染读取同一份数据。plan.json 的镜头与beat按该表派生或引用，不能手工维护第二份竞争时间。现有知识任务表和音效表继续分别负责阅读、音乐映射与SFX起音；不新增所有旧计划都必须填写的字段。

## 不同风格的可见响应

| 音乐任务 | 水墨 | 烟雨 | 理论概念 |
| --- | --- | --- | --- |
| 强重音 | 墨滴接触、山峰拔起 | 笔锋落下、月出水面 | 关系闭合、公式拼合 |
| 连续快音 | 连珠墨点、山脊递生 | 雨线、花叶生长 | 向量或对象依次显现 |
| 渐强与释放 | 江流贯通、镜头拉升 | 从器物进入山水 | 局部模型展开到整体 |
| 长音与留白 | 远山淡出、河流延伸 | 雾带缓移、曲面高光 | 连续轨迹、关系保持 |

这张表是选择动作的起点。控制单一主焦点，强弱采用相对层级，不规定每拍切镜、固定闪光或事件数量。真实关系、阅读和理解时间优先。水墨需要体块与浓淡遮挡，烟雨需要材质与远近雾层，理论需要数学或机制对应正确。

诗词与乐器主题补读 [诗词音乐世界](poetry-music-world.md)，把唱词意象、乐器接触、景物与立体诗字组织成可见接力。声音时间与可变速运动分别处理，停顿、爆发和人物自然度按实际画面与声音复验；不新增固定曲目或强制人物模板。

## 两条制作路线

先沿 [音乐镜头与运动编排](music-shot-choreography.md) 与 [编排模板](../templates/music-direction.md) 明确场景发展、开场、主动作、运镜和接力，再选择路线。慢歌同样由唱句、旋律、呼吸与重音带动画面；三维环境、雨雾或粒子存在不代表已经完成律动、具体场景与叙事。

先复用已有项目。无对应工程时，用 `assets/music-world/starter` 起步，再按主题修改实际几何与关系。

- Three.js＋Remotion适合可计算几何、公式和快速重排。`core/state.mjs` 按帧计算状态、固定种子；`src/index.tsx` 组织主题对象、稳定文字与音轨。理论内容不能仅换标题，需实现并核验关系。
- Blender＋Remotion适合器物、地形与材质。`blender/render.py` 读取同一事件与音乐配置，逐帧计算几何与相机，串行输出画面；Remotion合成实际帧、字幕与音轨。保存的单帧场景不冒充完整烘焙动画。

初始化只复制小代码和配置，不复制歌曲、私人工程、缓存或依赖。优先复用兼容环境；缺失能力先探测，具体接口按宿主外部技术规则核实。跨引擎分别检查坐标、镜头投影、色彩和音画时钟。

```sh
python3 SKILL_ROOT/scripts/music_world.py init --music /project/song.wav --theme "潮汐与月引力" --style 理论概念 --into /project/tide
python3 SKILL_ROOT/scripts/music_world.py analyse --project /project/tide
# 实际核听、调整选段/事件、实现主题，并记录实际完成范围
python3 SKILL_ROOT/scripts/music_world.py validate --project /project/tide
```

`init` 不覆盖已有工程；`analyse` 不覆盖已编排的 score.json，只另存 score.candidate.json；`validate` 拒绝旧音乐身份、片段或帧率不一致、破损音轨、重复事件与非法阶段，生成渲染输入。它只证明结构，不证明主题或听感通过。

## 质量、成本与修改

锁定音乐和主题关系后再调整前中后景、材质、光影、镜头、景深和冲击。每个外观层能独立关闭做同镜对照，不能靠加亮、加密、加颗粒替代内容。镜头在接触前到位，关键结果后留清晰停留；附着文字随场景同动，底部字幕保持屏幕稳定。

优先按帧计算、固定随机种子；顺序依赖模拟先烘焙或标记范围，不能声称任意seek。重渲与编码默认串行，限制线程；已有帧、母带和兼容依赖能复用就不重建。

换音乐、截取、速率或帧率后重建特征、事件映射、字幕和受影响画面，旧同步与听审状态失效。只改文字复用画面；只改后期复用原始帧；改动作才重渲相应范围。实际保留与清理按本任务资源归属决定。

核对实际导出片中的接触、峰值、落定和停顿，检查前后连续帧并播放关键区间与整片，听字幕与演唱、音乐瞬态和视觉响应、尾音及接缝。机器时刻、抽帧、连续观看、听审和观众理解分别登记；未完成检查保持对应状态，不为“直接交付”伪造通过。

最终交付有声视频、必要可编辑源、音乐线索、事件表、实际检查及资源说明。案例的风格、片长与引擎不成为全局默认；原作品的指标和认可不继承到新主题。
