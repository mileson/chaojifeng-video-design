# 参考片研究：把一部成片拆成可迁移的方法

用户给一部成片，要“研究它的手法、抽象成可复用的方法”时读本文。目标是留下**换了产品也成立的规则**，不是复刻这部片。已抽出的发布片元素见 [发布片语法](launch-film-grammar.md)；那是用本文方法做出的一个结果，不是研究的终点。

## 研究流程

| 步骤 | 做什么 | 工具 | 产出 | 证据 |
| --- | --- | --- | --- | --- |
| 1 登记 | 路径、哈希、规格；写下“没有什么”（无旁白、无字幕） | `film_probe.py` | 规格与缺项清单 | E2 |
| 2 找源 | 看片内标题、水印、文件名、用户线索，是否有公开源码；有公开 GitHub 项目先走 DeepWiki 取架构，取不到再取固定提交的原文并记录提交号 | DeepWiki、固定提交原文 | 源码时间轴、缓动、文案 | E1 |
| 3 切结构 | 检测切点并分场景；与源码时间交叉核对，不一致就查原因 | `film_probe.py` | 切点表、场景占比 | E2 |
| 4 看帧 | 每段看首帧、最密帧、落定帧、转场边界；先看联系表再对关键时刻看单帧 | `film_probe.py --sheet-step` | 观察笔记 | E2 |
| 5 测声 | 响度、能量谷、起音；与画面事件对表。**没听就写没听** | `film_probe.py`、`audio_event_audit.py` | 声音事件表 | E3 |
| 6 记台账 | 每条观察带时间、证据级别、原始数字 | — | 观察台账 | E1–E3 |
| 7 抽象 | 过抽象阶梯（下节），追踪场景、视觉角度、构建机制与动效的关系 | — | 方法或元素草案 | E4 |
| 8 记瑕疵 | 参考片自己的问题也记下，作为反例 | 同上 | 反例 | E1–E3 |
| 9 落笔 | 先判断归属：补现有方法；有独立复用价值时才建表达或配方，写来源与边界 | 方法文档、按需用 `catalog.py` | 方法、表达或配方 | — |

探测工具只做测量：切点来自帧差，音频事件来自能量包络，调色板是 3×3 区块平均，参数见各脚本 `--help`。交叉淡化的检测起点晚于真实起点，慢速渐变可能漏检，阈值越低越容易把界面内动画当成切点；有源码时以源码为准。

## 抽象阶梯

每条结论从下往上走完才升格为元素；走不完就留在观察里。

| 层 | 问 | 例 |
| --- | --- | --- |
| 观察 | 画面或声音上发生了什么，证据是什么 | 9.3–12.3 秒先出现 AI 总结的长文墙，再出现 *Still too long* |
| 意图 | 创作者想让观众得到什么（标推断） | 让观众自己看出常规办法也不行 |
| 原则 | 去掉这部片的具体内容仍成立的规则 | 失败的替代用它自己的产出示范，不用旁白贬低 |
| 起点参数 | 这部片的数值，标成参考，不是默认 | 每层 1–3 秒，判决语 1–3 个词 |
| 边界 | 什么时候不该用、怎样会失败 | 替代方案是稻草人；痛点已为人熟知 |
| 迁移测试 | 换一个完全不同的产品，写得出对应画面吗 | 修图小工具：直接发方图 → *Too square*；用修图软件 → *Too many steps* |

规则：

- 原则必须能脱离这部片的内容陈述；说不出来的就只是观察。
- 参数写成“参考起点”，不写进目录的可执行字段。
- 分清创作选择与工具限制：同一做法可能只是当时工具的结果。
- 同源素材不当两个独立样本。例：用户给的 `full-film.mp4` 就是 HyperFrames「PR → Video」项目的成片（片内标题与切点同源码时间一致）。
- 一部片只能支持“这种做法存在且做得出来”，不能证明“有效”。

## 从视觉关系追到构建机制

研究代码视觉、交互动画或 B-roll 参考时，将 [场景到画面的推导](design-method.md#场景视觉角度代码与动效一起推导) 反向展开。保留可见关系与选择理由，不只收集形象、颜色或动效名称。

| 研究对象 | 要记录什么 |
| --- | --- |
| 场景与视觉角度 | 原场景在表达什么；画面把哪种关系变成了空间、形态或状态；为何贴切。前者依据内容，创作者意图未知时明确为研究者推断 |
| 可见联动 | 什么触发什么，哪些对象保持身份，方向、位置、遮挡与结果怎样相互约束；记录实际观察时刻和范围 |
| 代码构建 | 有可信原始源码时核对状态、几何、时间与实现位置；没有时只写可行的重建假设，并列出待验能力。外观或评论区猜测不能证明原作使用某库或渲染器 |
| 动效表达 | 主变化、响应、停留与视线交接各服务什么意义；静态会失去什么，去掉某层运动会不会更清楚 |
| 风格语法 | 轮廓、线条、材质、字形、层级和运动气质怎样配合；哪些承担语义，哪些只是这个案例的选择 |
| 迁移与反例 | 换成不同内容关系时重新选主体和构图，写出代码机制与动作怎样相应变化；只换形象或调色不算迁移 |

在笔记中分清四类内容：**实际观察、表达意图推断、经源码核验的原作实现、自行提出的重建方案**。看不到源码不妨碍提炼方法，但不能把重建方案写成原作技术事实。抽帧能支持构图和离散状态观察；连续速度、缓动、响应延迟与整体节奏需要播放验证，不能由稀疏帧确定。

通用决策归入 `design-method.md`，代码映射归入 `expression-method.md`，稳定风格规则沿现有风格包管理。一个案例不自动产生新 Skill、新风格或新目录 ID；只有表达职责、参数和边界确实可独立复用时才按扩展合同建条目。观察素材与实现证据留在研究项目，分发文档记录来源和证据边界。

## 有创作对话时，追踪决定怎样变成产物

先锁用户指定会话与时间范围，做结构扫描，再回读实质指令、纠正、关键版本和对应产物；排除系统注入、自动回执与无关信息，不将模型思考或自述当成用户确认。只读取所需材料，不因一个会话ID扩成全历史扫描。没有原片时可研究过程，不能宣称看过或听过作品。

| 要追踪的关系 | 记录与核对 |
| --- | --- |
| 指令 → 选择 | 观众、用途、片长、声音或渠道约束何时变化；原话与Agent解释分开 |
| 版本 → 成片 | 哪个计划、代码、素材与最终哈希相对应；早期联系表不能代表新版 |
| 主张 → 证据 | 当前产品行为、事件来源和真实结果；生成素材、重建、比喻分别承担什么 |
| 素材 → 派生 | 哪份原图/音频被裁切、分层、生成或重绘；接受依据、丢失记录和未核内容 |
| 失败 → 修改 | 原方法、可核现象、改动及残留；未重跑或未听审的部分保留缺口 |
| 指标 → 结论 | 采样帧率、阈值、总数与审计子集；仪器结果不替代审美、听感或传播 |

沿原版本保留失败条件，再做“原则→边界→换产品”的迁移。用户在单片中删说明或导流，只证明该片限制；固定色彩、性别审美、BPM、时长和运动量不升为默认。单案例可形成guidance候选，不能晋升跨场景有效的方法。产品歌唱与前三秒可按 [产品音乐叙事](product-music-story.md)、[开场设计](opening-design.md) 检查可迁移关系。

研究报告可保留私有原始材料入口，通用Skill只纳入方法、匿名化失败条件与来源边界，不打包对话、个人声音或项目素材。

## 反例与瑕疵

参考片不是满分答案。该片开场音效没有跟着画面重排（见 [发布片语法·声音](launch-film-grammar.md#三声音先写事件表再排时间线)），就是用本文第 5、8 步发现的。记反例时写清：证据、推断、是否被听过、对应的预防办法。

## 归属与分发

- 不打包原片、画面、音乐、字体、品牌与界面；示例和测试只用合成素材。
- 引用固定提交的链接，不复制源码；商业字体、素材的许可另核。
- 来源链接和边界写进 [sources.md](sources.md)，没读过的部分写没读过。
- 用户给的片是私有素材时，只在本机研究，笔记里不出现可还原原片的整段内容。

## 产出清单

- 观察台账（时间、证据级别、数字）、联系表和关键帧
- 方法或元素草案：观察→意图→原则→起点→边界→迁移测试；涉及代码视觉时附场景、视觉、构建与动效的对应理由
- 反例与未验证清单（没听、没做观众测试、没看某些段）
- 落地的现有方法修订，或确有独立价值的目录条目与配方，及它们与既有内容的关系（不重复造 ID）
