# 产品宣传视频

让目标用户看见产品能带来的结果、理解关键价值，并记住产品。场景 ID 为 `product-promo`；产品演示可聚焦一次操作，产品宣传要把这些操作组织成完整的价值表达。音乐视频仍沿原分支；明确要求歌词或乐段主导的产品片可组合 `product-music-story`。

## 三种入口

| 入口 | 用户提供什么 | Agent 怎样开始 |
| --- | --- | --- |
| 参考素材 | 参考视频、图片、工程或创作对话，加产品入口 | 读取真实可用素材，拆出首幕、主体、尾幕、版式、声音和节奏；区分用户明确要求、可见结果与自己的推断，再映射到当前产品 |
| 模板名称 | 已登记的模板名称，加产品入口 | 按名称／别名／稳定 ID 精确查配方，加载对应模板，沿模板补齐产品事实和素材；不要求用户再找参考片 |
| 产品源码 | 产品源码目录，加几项选题侧重点 | 沿[源码说明片](product-source-explainer.md)读源码建事实账本，把侧重点映射成章节，取当前版本的真实证据，再用极简左右讲解的视觉语法制作；不要求用户另给参考片或截图 |

同时给了几种入口时，明确指令优先：源码负责事实、限制和证据，模板与参考只覆盖被指定的版式、节奏和声音维度。参考未能读取时如实记录，继续可用证据；不能声称已复刻。未知模板名先返回可选模板，不悄悄换成同名近似项。首次只说“做产品宣传视频”，且目标是清楚介绍产品时，可直接选“极简左右讲解”并说明选择；用户给了源码目录和想强调的重点时选“源码说明片”。

这三种入口是输入方式；计划中的 `mode` 继续使用 `recipe / compose / free`。采用本模板时使用 `scenario_id: product-promo`、`mode: recipe`，在项目分镜中登记 `recipe_id: product-split-explainer`（源码入口登记 `product-source-explainer`）与实际入口。无需为此改变计划合同或发明渲染 API。

```sh
python3 SKILL_ROOT/scripts/catalog.py --kind recipe list --scenario product-promo
python3 SKILL_ROOT/scripts/catalog.py --kind recipe get 极简左右讲解 --json
python3 SKILL_ROOT/scripts/catalog.py --kind recipe get 源码说明片 --json
```

## 从一句话走到成片

1. **从产品补上下文。** 读取项目说明、适用规则、现有素材和实际功能，核实名称、平台、版本及关键价值；给了源码和侧重点时，调研与事实账本按[源码说明片](product-source-explainer.md)进行。复用现有制作能力和获准资产；新的制作放独立输出目录，避免覆盖旧成片或无关代码。没有说明受众时，从产品实际用途选择主要用户。新视频未指定画幅默认 9:16（1080×1920），明确指定的 16:9、1:1 等比例优先；局部修订保留已有画幅。先把宽高写入计划，再设计分镜和安全区域。参考片的画幅与视觉方法分别记录，只参考风格不等于要求同画幅。
2. **挑能证明的价值。** 选择少量完整使用场景，每段对应可见的操作与结果。功能清单只用于检查覆盖，不直接当脚本。真实截图、录屏和作品优先；工程重建需与产品状态核对，来源记录在内部，不能演出不存在的功能。
3. **先写首尾，再串主体。** 用开场承诺确定主体必须证明什么；结尾回收相同作品、任务或品牌视觉。为各段写短标题、口播意图、画面证据和稳定阅读窗。详见[极简左右讲解](../templates/product-split-explainer.md)。
4. **用真实声音排时间。** 讲解型默认采用自然、亲切、有把握的连贯旁白和背景音乐，用户指定声音方案时优先；超级峰自己的产品和内容按 [讲解配音的声音方向](narration-voice-direction.md)，用其授权的本人声音，语速偏快、有起伏。需要本地参考音色旁白时沿 [Qwen 配音接入](qwen3-tts-narration.md) 检测、复用或按需补齐，不要求用户自行找模型。先获得实际配音，再按句子和停顿排镜头、字幕及尾音，不照抄参考片时长或强塞固定秒数。可先以约 45–75 秒规划，实际以完整表达和音频为准；明确时长约束则在配音前压缩稿件。
5. **持续制作并验收。** 读取既有制作、声音和交付流程，探测真实可用能力。短段检查由 Agent 内部完成；用户要求成片时连续完成整片与必要返修。某个配音／渲染工具失败，先检查现有日志和可用回退；不能静默删除旁白、音乐或必需镜头来凑出文件。

## 首尾两幕共同约束

**产品说明类默认先让观众有疑问。** 用户 2026-11-05 的要求：产品类讲解先说“你是不是遇到过这样的情况”，引起共鸣，再给解决方案，再讲怎么操作。第一幕因此可以是钩子（观众的麻烦、顾虑与疑问，约 14 秒）加揭晓；“我会得到什么”由揭晓之后的第一个结果来回答。做法见[源码说明片·开场钩子](product-source-explainer.md#开场钩子)，其中顾虑要单独过边界，不能被说成产品承诺。用户明确要结果先行，或产品没有观众一听就点头的麻烦时，按下一段的写法。

**第一幕要回答“我会得到什么”。** 采用独立的首幕构图，不沿用主体的讲解框架。可用少量清楚的完成作品或核心结果引出产品，也可按明确参考采用品牌图形与具体承诺；两种方式都要尽快说清用途，避免长 Logo 等待或空泛功能清单。开场展示的结果必须在主体得到解释。原片约三秒的品牌开场只作节奏参考，不变成所有产品固定时长。

**最后一幕要让价值落定。** 让主体操作界面退出，回到完成作品或核心成果，以独立构图呈现产品名和一句自然的品牌收束语；复用开场的图形、作品或关键句形成呼应。给观众看清与听完的时间，避免重复长篇介绍。声音保留完整尾句、尾音和自然淡出，不用突然黑屏掐断。用户明确要求转化时才加入已核实的下载、购买或访问入口；纯介绍不强加号召或虚构地址。

## 声画与文字

- 旁白像了解产品的人向用户讲清价值：句间有因果与承接，画面展示具体操作和变化，避免逐条念按钮与功能名。无依据的效果、数据、用户评价和个人经历不写入稿件。
- 背景音乐清楚可听，人声期间适度降低，停顿或纯画面处可恢复；完整混音后实际听审，响度数值和转写只能辅助。复用已有音乐要核实来源与使用范围，参考片含人声时不能整条音轨混入成片。
- 标题用短句，字幕紧跟实际发声并按语义分组。语言沿项目或用户要求，否则沿[字幕规则](subtitle-direction.md)。该模板选底部固定字幕，不能被通用空间字幕建议改成满屏游走文字。
- 独立展示的标题、短行及字幕可去掉末尾句号、逗号（含中英文），保留句内必要标点、问号及真实界面原文；配音稿仍保留自然停顿所需标点。
- 对外文字、文件名和音轨直接采用受众表达；来源、重建方式、工具和执行记录留在内部，不加制作身份标签，也不把推断写成真实业绩。

## 验收与边界

先检查首幕、至少一个完整主体段及尾幕，再通看、听审实际导出版本。按目标画幅缩到实际观看尺寸检查，竖版可从 360×640 的预览起步；整机看不清就放大当前操作或切近景，不靠看大图通过。逐项回答：结果能否看清、操作是否兑现口播、同一作品是否连续、标题和字幕是否遮挡、品牌收束是否完整、旁白音乐是否都听得清。列出首尾实际时长和占比，检查是否挤压产品证据；不用统一时长比例代替判断。改配音需重新量时；仅改图片或字幕时保留已确认声音及其他镜头。

交付可播放成片、必要编辑源、素材引用和实际验证摘要。结构检查、导出探测、画面查看、完整播放和听审分别记录，未执行的项目保持未验证。模板属于可执行创作指导，具体渲染依赖宿主能力；来源案例的成功不等于当前作品已通过。
