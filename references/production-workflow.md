# 从计划做到成片

代码路线按 [执行合同](execution-contract.md) 将必要动作与字幕绑定到主计划和实际对象，接通统一采样与状态回读。每阶段形成下一步使用的依据；难段验证和返修由 Agent 内部完成，direct 连续推进，不额外设置用户确认门禁。

1. **定主线、画幅和导演意图。** 新视频未指定画幅默认 9:16（1080×1920），用户明确比例优先；已有作品局部修改保留原画幅。先确定计划宽高，再安排分镜、主体、字幕和安全区域。 明确观众起点／终点、贯穿线、结构理由、真实依据与必须保留的身份。定义人物、产品、物体或概念的使命，提前安排声音与能量起伏；“科技感”要落实到内容相关的视觉和听觉选择。简单片写 plan.design.rationale，复杂片用可选 plan.director 和 [导演模板](../templates/director.json)；[方向模板](../templates/direction.md) 按需展开。不复制参考作者经历或把示例数据当事实。
2. **写镜头任务与可编辑计划。** 使用 [计划合同](plan-contract.md) 与 [最小模板](../templates/plan.json)。每镜明确新增的信息／感受、焦点、揭示顺序、镜头目的、下一镜接力与稳定停留，可记 scene.intent。需要框选界面、解释操作或突出证据时读 [视觉强调与动态标注](visual-emphasis.md)，先定义目标与保护区域，再安排标签、引线、局部聚焦及进退场；相机与标注共用正确映射，不遮字幕和关键内容。时间用整片绝对秒，镜头／对象／节拍／旁白／素材有稳定ID。产品与知识不强加人物冲突；音乐片不强加三幕。
3. **落实素材与时间。** 优先用户素材和真实产品/数据证据；事实画面缺素材时先联网检索原始来源，记录候选、权利、选用／排除理由及停止条件，再补图表或非证据生成画面。按镜头使命规划图层、主动作与跨镜接力，复用能完成任务的现有执行器。代码绘制、程序化音效同样留实现。模型、生成器、下载内容和素材包不能隐瞒；用户限制单模型时严格守住边界。
4. **声画一起排练。** 按 [声音与节奏](sound-and-rhythm.md) 确定主声、动机、起落与静默。选配乐时读 [音乐导演与选段](music-direction.md)，先写各段情绪与职责，再从 [音乐图册](../assets/music/index.html) 或查询脚本找候选片段，记录原曲时间与成片落点；可整曲贯穿、同曲分段或跨曲组合，不默认整首循环。区分实测、导演推断与已试听，素材和使用范围先核实。有旁白时取得真实音频并测逐句时长后排视觉节拍；估时只能标 estimated。用 beat_id 关联视觉和声音，不宣称自动词级对齐。音效较多时先写 [事件表](../templates/audio-event-map.json)（排程时刻=动作时刻+起音偏移，同一份数据生成），时间重排后重新生成，渲染后拿无音乐的音效分轨交给 `audio_event_audit.py` 核对，方法见 [发布片语法·声音](launch-film-grammar.md#三声音先写事件表再排时间线)。用户要求声音时，听觉方案和实际音轨都是交付的一部分。
5. **按约定节奏完成制作。** direct 直接生成完整可编辑源与成片，在同一轮内检查并修复难段，不以试片或方向确认中断；其他任务可先用关键帧／短段／粗剪检验主线、阅读窗、声画落点与接缝，再继续完成，只有用户要求 staged 时等待确认。允许精确分镜或有边界探索；为失败镜头保留替代表达与停止条件。看首帧、最密帧、关系落定帧、转场边界与连续播放。统一时钟和随机seek只有实测一致时才能宣称。具体 API 查当前文档，不凭记忆拼参数。
6. **审片、导出、交付。** 完成所需完整渲染，保存源、视频与 [交付记录](../templates/delivery.json)。按 [审片与修改](review-and-revision.md) 实查声音、画面、审美、节奏、叙事和科技感，另核事实、播放与产物一致性。按实际观看尺寸检查可读性，竖版可缩至 360×640 核对；核导出宽高与计划一致，主体及字幕不因裁切或缩放而丢失。已知错词、明显字幕错位或不符任务的长等待先返修，不以披露缺陷代替满足必要要求；尚未解决的版本明确为候选／未通过。记录当前计划与文件哈希；未看、未听、未做观众测试的项目保持未验证，不保证审美结果或理解提升。

音乐驱动三维作品先按 [专项流程](music-driven-world.md) 取得真实音轨、候选分析与有效事件，锁定音乐/主题后再调外观。专项工具只生成分析和起步工程，Agent继续实现本片关系、渲染、实际视听及交付。

音乐片的具体决策沿 [声画事件模型](music-event-model.md)：分层锚点→情绪与事件前后变化→视线与运镜→峰值落点→空间材质→感知验收。每个关键事件用模板中的七项卡贯通设计、实现与复验；先低成本预演开场与首个关键声音落点，在目标观看尺寸和正常速度下验证，再扩展全片。看不出预期变化或关键材质失真时，回到事件、镜头或资产路线调整，不以增加动画参数或效果数量放行。仅缺少观看／听审能力时如实保留对应缺口，不伪造通过，也不自动增加用户确认门禁。

音乐主导画面先按 [字幕导演](subtitle-direction.md) 取得有演唱区间的歌词时间线，再沿 [歌曲视觉导演](song-visual-direction.md) 和 [音乐镜头与运动编排](music-shot-choreography.md) 将真实乐句与证据、场景发展、开场、镜头事件、主次运动和声画落点写进已有计划或 [编排模板](../templates/music-direction.md)。慢歌同样由音乐带动画面，按乐段安排速度、幅度、密度与情绪力度。先落实关键镜头所需资产与执行能力，内部预演开场、音乐转折和关键转场并返修，再完成整片。direct 不设置用户试片确认；静帧、信号候选和结构通过不能替代听审或实际运动检查。歌词识别或制作能力不足须保留具体尝试与缺口，不能静默省略字幕或退回无发展的空镜。
