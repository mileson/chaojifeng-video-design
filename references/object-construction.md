# 物体形象构建

内容需要某个物体或现象时，按“元素＋表现重点＋镜头尺度”匹配构建方法。咖啡表面的倒影、玻璃雨滴的滑落、浅水下的光纹虽然都涉及液体，需要的形态、运动和光学并不相同。

这是元素级配方，服务已经确定的镜头内容，负责物体怎样形成、怎样运动、怎样受光以及怎样与环境接触。整片故事沿用导演方法，画面气质沿用风格包，动作和镜头绑定同一主时间线。

## 使用方法

1. 从内容找元素：明确它在本镜头中的作用，不因为效果好看就强加进来。
2. 从元素找表现重点：轮廓、光泽、流动、形变、碰撞或关系变化；明确观众必须看清什么。
3. 从镜头找构建条件：尺度、距离、边界、相机、照明、可用引擎和成本。
4. 选择构建配方，在确定实现路线之前读取方法与工程指南；同一元素可有多种方法，同一方法可迁移到不同元素。
5. 将表现目标绑定到实际实现能力，禁止为方便出片自行降低已确定的效果目标。用实际导出的关键连续片段验证画面和变化，核心项通过后再完成整片。复现须保留本项目的几何、材质、参数、事件、相机、种子和时间状态。

液体配方的阅读不以“已经选择三维”为前提。液体为表现主体且无用户或既定作品的明确平面要求时，默认三维构建；按配方入口执行，不能先自行选择二维来跳过工程指南。

## 与现有计划连接

继续使用 plan 中的 scene、element、motion、beat 和 asset ID。元素配方在项目笔记或镜头构建卡引用；只有配方主导整片时才作为 design.recipe_id，不覆盖已有整片配方。实现文件写入 execution 的对应 binding，局部依赖写 inputs，跨元素关系写 uses；参数变化的返修范围沿执行合同处理。

构建卡记录液体参数与动作关系，事件时间引用主计划 ID，不维护第二份时间表。资源与产物沿 production-job／delivery 记录，不另建重复素材台账。

## 持续扩展

新配方沿现有 recipes 目录登记稳定 ID、名称、匹配词、表现目标、构建步骤、参数关系、失败条件、回退和验证问题。详细方法放在对应对象目录，入口保持轻量。只有稳定且可重复使用的经验进入通用方法；单个项目的审美选择和未验证猜想不升级为默认规则。

扩展要说明哪些原理保持，哪些形态、边界、尺度、运动和光学需要替换，以及怎样重新验收。不能只换名字、颜色或模型就宣称扩展完成。
