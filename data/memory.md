# 项目经验

公开版不附带私人运行记录。仅在实际任务完成后记录可核验的结果；未观看、未听审或未做观众测试的项目保持未验证。不要保存密钥、私人素材或原始长对话。

- 2026-10-27：音乐驱动分支以音乐、主题、风格启动；保留用户指定歌曲，截取作品时同时截取原声画。三段15秒公开片均为1080p30、双声道AAC，音频与原片对应区间相关性超过0.999。起步工程完成Three.js路线60秒导出、Blender路线2秒画面与音频合成及随机seek状态检查；这些是工程验证，不代替新主题的视听与理解检查。
- 2026-10-28：用用户提供的 30 秒歌曲片段做 9:16 音乐视觉（一镜到底的雨窗房间）：WebGL2 程序化场景经 Chrome+Playwright 逐帧渲染 900 帧、ffmpeg 编码，音轨 stream copy 后与原曲 PCM 逐字节一致；无 ASR、无回听能力，因此不写唱词，audio/playback 保持 partial，comprehension not_run。validate_plan 0 错误，check_delivery 通过（status partial）。
- 2026-10-29：用户给 30.016s 音频（title「阴天 · 房间 9:16」），做成 9:16 1080x1920 30fps 音乐视觉《阴天 · 雨窗》：六个焦距讲同一块玻璃（微距水珠→整窗雨幕→水珠里的倒街→起雾→玻璃上的影子→最后一滴+片名）。玻璃层用 WebGL 折射 shader（UNPACK_FLIP_Y 修上下颠倒、fbm 替 hash 去马赛克、菲涅尔边光救回黑点状水珠、倒影按「暗于玻璃」处理），Chromium+Playwright 900 帧、ffmpeg CRF20 约 25MB；音轨流复制 packet md5 与 PCM 均与原文件一致；validate_plan 0 错误，check_delivery valid=partial（playback/audio partial、comprehension not_run，无回听与观众测试）。
- 2026-11-05：访谈解读（Economist 对吴恩达的访谈，原片 7 分 06 秒）做成 5 分 31 秒、1920×1080、25 fps 解读片，7 段引语合计约 99 秒（原片 23%），本地 TTS 授权音色配音，叠加层 Playwright 渲染、ffmpeg 合成；−16.0 LUFS、真峰值 −1.4 dBFS，口播回听汉字错误率 0.015，英文引语字幕召回 0.966。说话人嵌入相似度对本人与他人英文素材都在 0.95 到 0.98，不能当作音色相似证据；听感与观众理解未验证（not_checked / not_run）。
- 2026-11-05：同一期访谈解读做 `-v2`（5 分 23 秒，1920×1080、25 fps）：旁白改用用户指定的云端克隆音色（火山声音复刻 2.0，45 句、224 次请求，预计 1.82 元），加一条背景声音（剪映素材库缓存，口播下约 −18 dB）与 47 个音效事件（每分钟 8.7 个，三层，访谈段内无音效）；音效起音审计 47/47 ok，含声音后口播回听汉字错误率 0.009，−16.0 LUFS、真峰值 −1.3 dBFS。素材库商用许可未核实；听感、音色相似度与声音取舍未听审（not_checked）。
- 2026-11-05：同一期访谈解读做 `-v3`（5 分 25 秒，1920×1080、25 fps），按用户第三轮反馈：画面改为图表优先（24 种场景，图形画面占 77.1%，最长纯访谈段 13.96 秒）；本机 ACE-Step 1.5 生成 5 段铺底（按章节更换）与 19 种音效（86 个事件，每分钟 15.9 个，高于 v2 的 8.7 个），铺底相对人声（300 Hz 到 3 kHz 强语音帧）均值 −30.2 dB；字幕句末不带标点；署名去掉“素材 · ”；收尾屏幕上不放评论邀请，另做一段 6 秒可复用的品牌落款（16:9 与 9:16）；−16.1 LUFS、真峰值 −1.4 dBFS，抽窗回听汉字错误率 0.009。踩到的坑：叠层帧里混了不带透明通道的整屏图，ffmpeg 静默丢掉后面的长叠层（补成带透明通道，并逐段核对叠层在位）；ACE 的噪声类音效带约 31 Hz 调幅，扫音改用合成噪声。这些都是工具实测，听感、音效密度是否偏高、ACE 商用授权与用户验收均未完成（not_checked）。
- 2026-11-05：源码说明片首次实战（Chrome 扩展“一键发”，源码 0.1.74，用户侧重点：一键发布多个平台、内容搬运、多账号运营）：账本 15 条事实、10 条边界、11 份证据、16 条口播主张，`product_ledger.py check` 0 错误 0 警告；真实界面用产品自带夹具经 Playwright 无头 Chromium 逐帧渲染 2448 帧，通用合成声旁白，本机代码合成乐床与 33 个界面音效；成片 1080×1920、25 fps、97.9 秒，−14.5 LUFS、真峰值 −3.5 dBFS，混音回读字错率 0.54%（同音字）。`validate_plan.py` 严格模式 0 错误 0 警告，`check_delivery.py --probe --require-video` 通过（status partial）。未做整片连续播放与人耳试听（visual／playback／audio partial），观众理解 not_run；产品授权声明与商店 0.1.73 对源码 0.1.74 的差异留给产品方核对。
- 2026-11-05：源码说明片第二版（同一部“一键发”介绍片）：用户听完第一版反馈音色单调、语速慢，要求用超级峰的音色复刻并更有激情。旁白改用已有的云端克隆音色（火山声音复刻 2.0），16 段口播各取 6 个样，按字准率、语速、音高与响度起伏择优，共 226 次请求、约 1.66 元；整体语速 3.72 → 5.84 字/秒（有声段 4.32 → 6.70），片长 97.9 → 63.0 秒；画面按口播起止点做分段线性时间映射，乐床提到 108 BPM，字幕、33 个音效、计划与交付登记同步重做；43 个分句边缘经波形核对无可疑项，−14.4 LUFS、响度范围 1.0 LU、真峰值 −3.0 dBFS。情绪提示文本、`<cot>` 标签、模型子型号参数对该克隆音色没有可测影响，感叹号反而让语速变慢。激情感、像不像本人、音效疏密均未听审（not_checked）。
- 2026-11-05（偏好）：讲解配音类作品，用户多次反馈：旁白用超级峰本人的声音，语速偏快，要有激情与感染力，配乐不压人声，音效落在情绪点，开头 5 秒有节奏与叙事；他用听感给方向，不给数字。取向、实测手段与边界见 [讲解配音的声音方向](../references/narration-voice-direction.md)。
- 2026-11-05：源码说明片第三版（同一部“一键发”介绍片）：用户要求开篇先有钩子，让观众有疑问、引起共鸣，再给解决方案，再讲怎么操作。开头新增痛点钩子四句（费时费力的提问、想用 AI 代发又怕限流封号的顾虑、公众号飞书 X 之间搬文章全靠复制粘贴、有没有一款能一键发能搬运账号分开管的疑问）加一句揭晓，原来的“点一下，五个平台都填好了”后移为揭晓后的第一个结果；三章与片尾的口播文字、取证和画面不变。新增 5 段口播共 61 次请求约 0.45 元，累计 287 次约 2.11 元；成片 74.6 秒，整体语速 5.62 字/秒（含停顿），有声段 6.53（钩子加揭晓约 6.0，正文约 6.7），−14.4 LUFS、响度范围 1.2 LU、真峰值 −3.1 dBFS；52 个分句边缘经波形核对无可疑项。乐床钩子段不进鼓，揭晓前留一拍真空、揭晓处落点并进鼓，新增三种音效（盖章落点、揭晓重击、上升音）。账本新增可选的 `framings` 登记开场里替观众说话的句子，顾虑句必须写明由哪条边界收住（脚本与单测同步）；钩子里的“AI 代发、限流封号”只作观众顾虑，片中不承诺通过审核或账号安全。未做整片连续播放与人耳试听（visual／playback／audio partial），钩子是否更抓人、语气与节奏是否到位均未听审，观众理解 not_run；钩子段语速比正文慢，是否需要更快待听后再定。
- 2026-11-05（偏好）：产品类讲解的叙事顺序，用户明确要求先抛观众的疑问与麻烦、引起共鸣，再给解决方案，再讲怎么操作；他给的钩子素材是“一份内容发多个平台费时费力、担心用 AI 被限流封号、想找能多账号一键发还能搬运的、X 与公众号飞书之间搬内容的痛点”。取向与做法见 [源码说明片·开场钩子](../references/product-source-explainer.md#开场钩子) 与 [讲解配音的声音方向](../references/narration-voice-direction.md#开场钩子的声音与配乐)。
